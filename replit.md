## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string
- Optional env (reminders): `RESEND_API_KEY` (email); `RESEND_FROM_EMAIL` — platform address used in the email "De:" header (e.g. `cobros@cobrosimple.com`; must be a verified domain in Resend). Emails send as `"<sender> via Cobro Simple" <RESEND_FROM_EMAIL>` with Reply-To set to the sending user. WhatsApp auto-send via Meta Cloud API: `WHATSAPP_PHONE_NUMBER_ID` + `WHATSAPP_ACCESS_TOKEN` (both required to enable); `WHATSAPP_API_VERSION` (default `v21.0`), `WHATSAPP_TEMPLATE_NAME` + `WHATSAPP_TEMPLATE_LANG` (default `es`) for business-initiated template messages. If unset, WhatsApp reminders fall back to in-app notifications.

## Product

- Chilean cobros/payments app. Auth is 100% custom email+password (no OIDC):
  registro (nombre, RUT único+validado, email, contraseña), login (recordarme,
  olvidé contraseña), recuperación por enlace 1h (Resend), verificación de email.
- Seguridad: bcrypt, sesiones por cookie, bloqueo tras 5 intentos fallidos (15min).
- Anti-abuso: 1 RUT = 1 trial de 14 días para siempre (`trialRutsTable`).
- Cuenta demo permanente (`esDemo`) y panel superadmin (cuentas, revenue, total
  recaudado, extender/activar/desactivar, buscar por ID/nombre/email/RUT).
- ID de cuenta público permanente `NCB-XXXXXXXXXX` (10 dígitos,
  `usersTable.accountId`, generado por la DB, inmutable): visible en Perfil, en
  el email de verificación de registro y como columna "ID" + buscador en el panel
  superadmin. IDs reservados: `NCB-0000000001` = superadmin, `NCB-0000000002` sin
  asignar, `NCB-0000000003` = cuenta demo; las cuentas nuevas parten desde
  `NCB-0000000004`.

## Ley 21.719 (data protection)

- Consent: register requires `aceptaPolitica===true` (non-prechecked checkbox);
  stored as `usersTable.politicaAceptadaEn`. Public legal pages at `/privacidad`
  and `/terminos` (third parties disclosed: Resend, Groq, Flow, MercadoPago).
- ARCO in Profile "Mis datos y privacidad": `GET /profile/exportar-datos` (JSON
  export of perfil+cobros+clientes, scoped by org role, never leaks
  passwordHash/credenciales) + `DELETE /profile/cuenta` (permanent, confirm
  "ELIMINAR"). Delete runs in a transaction; comprobantes deleted manually
  (no cascade), cobros children cascade by cobroId; `trial_ruts` preserved
  (anti-abuse); demo/admin blocked; org owner with other members → 409
  (re-checked inside the txn to close the race).

## Gotchas

- Account ID (`account_id` / `account_seq` in `usersTable`) is DB-generated:
  `account_seq` is an identity column, `account_id` is a STORED generated column
  (`'NCB-' || lpad(account_seq::text,10,'0')` — 10 digits). The app only READS
  `account_id`; the ONLY writer of `account_seq` is the startup seed, which
  inserts the reserved accounts with explicit seq (superadmin=1, demo=3) and then
  calls `ensureAccountSeqFloor()` to push the identity sequence to `MAX(seq)+1`
  (≥4) so real accounts get `NCB-0000000004+` and never collide with a reserved
  one (explicit inserts into a GENERATED BY DEFAULT identity do NOT advance the
  sequence). Uniqueness is structural (identity + deterministic formula),
  intentionally WITHOUT a UNIQUE constraint: adding UNIQUE to the populated
  `users` table makes `drizzle-kit push` demand an interactive truncate
  confirmation, which breaks non-interactive push (dev + prod deploys).
- Changing the `account_id` FORMAT (the `lpad` width): `drizzle-kit push`
  SILENTLY IGNORES generated-column expression changes — it prints "Changes
  applied" but leaves the old expression. You must alter it by hand in SQL
  (`ALTER TABLE users DROP COLUMN account_id; ALTER TABLE users ADD COLUMN
  account_id varchar GENERATED ALWAYS AS (...) STORED;`) — safe because the
  column has no dependents (no FK/index/unique) and re-adding recomputes every
  row. Prod picks up the new format from the dev-schema snapshot on next publish.
- Auth token consume (`lib/tokens.ts`) and login lockout increment
  (`routes/auth.ts`) MUST stay as single atomic SQL `UPDATE`s. Splitting either
  into SELECT-then-UPDATE reintroduces a single-use-token bypass / lockout race.
- Demo (anibal) and superadmin (agutierrez@nextcob.com) accounts are seeded with
  `passwordHash=null` + `emailVerified=true`; they set passwords via forgot-password.
- Email deliverability: `RESEND_FROM_EMAIL` is set to `cobros@nextcob.com` (shared
  env, dev + prod) and nextcob.com is verified in Resend, so mail now sends from the
  verified domain as `"<sender> via NextCob" <cobros@nextcob.com>` (Reply-To = sender).
  IMPORTANT: production picks up env-var changes only on the next publish/redeploy —
  setting the var does not update an already-running deployment.
  Note: the superadmin password-reset backup inbox (`SUPERADMIN_RECOVERY_EMAIL`,
  `getSuperadminRecoveryEmail` in `routes/auth.ts`) is now redundant and can be
  removed if desired.
